# ericlombardi.ca

Eric Lombardi's personal site: consulting, writing, media, public policy, events, support and
subscriber capture. A static site generated by `build.py` (Python 3, standard library only) into
`docs/`, which GitHub Pages serves at the custom domain.

## Layout

| Path | What it is |
|---|---|
| `build.py` | The generator. `python3 build.py` rebuilds everything into `docs/`. |
| `content/site.json` | Identity, navigation, socials, hero and sign-up copy, categories, and the switches for the form, analytics, support and the X feed. |
| `content/posts/*.md` | Blog posts (Markdown with a frontmatter block). |
| `content/media.json` | Columns, interviews and coverage. `kind` is `column`, `interview` or `coverage`; `campaign: true` puts an item in the 2026 campaign archive. |
| `content/events.json` | Where Eric will be. Upcoming/past is computed from the date at build time. |
| `content/policy/*.md` | Public-policy pages (leadership run, More Neighbours Toronto, Build Toronto). `_index.md` is the section landing copy. |
| `content/consulting.json`, `content/support.json` | Structured copy for those pages. |
| `content/pages/about.md`, `content/pages/privacy.md` | Long-form pages. |
| `assets/css/theme.css` | Design tokens: fonts, colours, radii. Change the look here. |
| `assets/css/site.css` | Layout and components. |
| `assets/img/`, `assets/fonts/`, `assets/js/site.js` | Images (placeholders for now), self-hosted fonts, the small script for the menu, filters and the form fallback. |
| `tools/new_post.py` | Scaffold a post. `tools/migrate_campaign_posts.py` was the one-time import from the campaign site. |
| `shots.js` | Full-page screenshots of every page at desktop and mobile widths into `build/shots/`. |
| `docs/` | Build output. Commit it; GitHub Pages serves it. |

## Preview locally

```bash
cd "/Users/ericlombardi/HSR Proposal/PersonalSite" && python3 build.py && python3 -m http.server 8788 --directory docs
```

Then open http://localhost:8788. (The desktop app's `personalsite` launch config does the same.)

## Publishing routine

1. Edit content (see below), then `python3 build.py`. Read the warnings it prints.
2. Commit and push:

```bash
cd "/Users/ericlombardi/HSR Proposal/PersonalSite" && git add -A && git commit -m "Describe the change" && git push
```

GitHub Pages redeploys within a minute or two.

1. Create a public repository (for example `ericlombardi-site`) under the `elombardi-website`
   GitHub account that already hosts the platform site, and push this folder to its `main` branch.
2. Settings → Pages → Source: `main` branch, folder `/docs`.
3. Settings → Pages → Custom domain: `ericlombardi.ca`. The committed `docs/CNAME` file already
   says that. Tick **Enforce HTTPS** once DNS has propagated.
4. At GoDaddy, for ericlombardi.ca:
   - Four **A** records on `@`: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
   - One **CNAME** on `www` → `elombardi-website.github.io`
   - Remove whatever `@`/`www` records point at the old host.
5. While the site is on the test address, build with
   `python3 build.py --base /ericlombardi-site --domain https://elombardi-website.github.io/ericlombardi-site`
   (no CNAME is written). For the custom domain, build plainly with `python3 build.py` and
   commit that instead. The local preview always wants the plain build.

## Adding content

**A post.** `python3 tools/new_post.py "Title" category` creates `content/posts/<slug>.md` with
the frontmatter filled in. Categories: `economy`, `housing-and-cities`, `infrastructure`,
`government`, `finance-and-technology`, `campaign-notes` (edit the list in `site.json`). Put
images in `assets/img/posts/` and reference them as `/assets/img/posts/name.jpg`. Remove
`draft: true` to publish. Markdown supports headings, lists, links, bold/italic, blockquotes,
images with captions (`![alt](src "caption")`), raw HTML and `<iframe>` embeds. A `canonical:`
line in the frontmatter is for pieces published first elsewhere.

**A column or interview.** Add an object to `content/media.json`:

```json
{"kind": "column", "campaign": false, "outlet": "The Hub", "format": "online",
 "title": "…", "date": "2026-11-02", "url": "https://…"}
```

`format` is `podcast`, `video`, `radio`, `print` or `online` and drives the filter chips.

**An event.** Add an object to `content/events.json`:

```json
{"title": "…", "date": "2026-11-19", "time": "6:30 pm", "end_time": "8:00 pm",
 "city": "Toronto", "venue": "…", "kind": "Panel", "url": "https://luma.com/…", "summary": "…"}
```

Leave `time` empty for an all-day entry. `url` can be a third-party registration page. Delete
the two entries marked `"placeholder": true` before launch (or build with `--no-placeholders`).
The events page, `events.ics` and `api/events.json` all come from this file.

**Public-policy pages.** Edit the Markdown files in `content/policy/`. `links:` takes
`Label|URL; Label|URL|primary`. `coverage: true` renders the campaign media archive.

**Cross-posting.** Write here first, publish, then paste the summary and link to LinkedIn, X and
Bluesky (the post page has share links). If a Substack ever makes sense, point it at
`/feed.xml`; the site is the canonical home.

## Switches in `site.json`

- `form.endpoint`: the email tool's form-post URL. Map its field names (first name, last name,
  email, postal code) in `form.fields` and add any hidden inputs it needs in `form.hidden`.
  While empty, the sign-up form opens the visitor's email app with their details addressed to
  eric@ericlombardi.ca. `form.consent` is `statement` (consent text under the button, quick)
  or `checkbox` (an unticked box the visitor must tick, the most conservative CASL reading).
- One Support page (`/support/`) holds both the free sign-up form (`#signup`) and the
  pay-what-you-want contribution. The home page keeps the quick sign-up bar under the hero.
  `/signup/` and `/subscribe/` redirect to `/support/`.
- `mailing_address`: CASL requires a mailing address in commercial emails; set it here and it
  appears under the form.
- `analytics`: Simple Analytics was used on ericforolp.ca. Add ericlombardi.ca in that
  account, then set `enabled: true`. Or put another provider's tag in `custom_snippet`.
- `support.contribute_url` (monthly, pay-what-you-want) and `support.one_time_url` (single
  gift), plus `support.live: true`, turn the contribution buttons on; `support.platform` is the
  name shown to visitors. A Stripe Payment Link with "customer chooses amount" covers both
  (needs a personal Stripe account; the existing one belongs to the campaign). Ko-fi or Buy Me
  a Coffee also work for pay-what-you-want. There are no tiers.
- `booking_url`: a Calendly or similar link adds "Book a call" buttons.
- `x_feed.enabled`: the X timeline embed on the public-policy page.
- `socials[].show`: which networks appear in the footer, contact page and JSON-LD.

## Machine-readable surface

`/feed.xml` and `/feed.json` (writing), `/events.ics` (calendar), `/sitemap.xml`, `/robots.txt`,
`/llms.txt`, and `/api/{site,posts,media,events}.json`. Every page carries JSON-LD (Person,
WebSite, WebPage, breadcrumbs; BlogPosting on posts; Event on upcoming events;
ProfessionalService on consulting), Open Graph and Twitter cards, canonical URLs.

## Design system

The site implements the "Eric Lombardi — Website design and voice brief" (Oct 2026, in
`~/Downloads/Eric_Lombardi_Design_and_Voice_Brief.md`; keep a copy with the project). Tokens
live in `assets/css/theme.css`; layout and components in `assets/css/site.css`.

**Typefaces (fixed pairing, self-hosted):**

| Role | Face | Files |
|---|---|---|
| Name, display statements, headings | Canela Regular (Light and Medium also loaded) | `assets/fonts/canela/` (Commercial Type web licence 2610-TCQESC; web-only, not installable on a computer) |
| Everything else: copy, nav, buttons, labels, forms, metadata | Manrope 400–700, variable | `assets/fonts/manrope/` (SIL Open Font Licence, from Google Fonts) |
| Sustained reading: essays, policy pages, about, privacy | Newsreader Text 400/600 + italics | `assets/fonts/newsreader/`, loaded by `reading.css` only on those pages |

The rest of the Newsreader package (Caption and Display optical sizes, all weights) is in
`fonts-staging/newsreader/`, which the build does not copy. Desktop TTFs are installed in
`~/Library/Fonts/`. PP Watch and PP Pangram Sans are no longer used on this site.

**Palette:** Midnight Ink `#172A31`, Architectural Ivory `#F5F1E8` (background), Limestone
`#E7E0D3` (secondary bands), Deep Petrol `#285B63` (links, buttons, selected states),
Patinated Bronze `#A6784D` (short rules, the hero frame, nothing textual), Slate `#617078`
(secondary text on ivory only). Every pair in use was checked against WCAG 2.2 AA; bronze is
never used for text.

**Detailing:** square corners (2 px), 1 px rules, no shadows, no pills. Three signature
details only: the short bronze rule beside major section labels, the offset frame around the
home portrait, and fine dividers between columns. Type scale, spacing scale (4 to 128 px),
content width (80 rem), reading measure (65 ch) and the 44 px control height are all tokens.

**Voice:** sentence case, Canadian spelling, no em dashes or "not X, but Y" constructions in
site copy. "A future worth building." is the working home headline.
